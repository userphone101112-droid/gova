# ADR-0001: Adopt Clean + Hexagonal Architecture for Backend

**Date**: 2026-06-01
**Status**: Accepted
**Deciders**: Platform Architecture Team

---

## Context

The backend API needed a scalable, testable architecture that allows swapping infrastructure components (database, auth, storage) without changing business logic.

## Decision

Adopt **Clean Architecture** (layered: Domain → Application → Infrastructure → Interface) combined with **Hexagonal Architecture** (Ports & Adapters) for the Fastify backend.

## Consequences

**Positive:**

- Domain layer has zero infrastructure dependencies — fully unit-testable
- Storage, DB, and auth providers are swappable via adapters
- Use-cases are independently testable
- Clear boundary between business logic and I/O

**Negative:**

- More boilerplate than a simple MVC approach
- Steeper learning curve for new developers

## Implementation

- `apps/api/src/domain/` — Pure domain (entities, value objects, errors, events)
- `apps/api/src/application/` — Use cases, ports, DTOs
- `apps/api/src/infrastructure/` — DB, auth, storage, logging
- `apps/api/src/interfaces/` — HTTP routes, controllers, validators
