# ADR-0002: Adopt SSOT Package Strategy for Shared Knowledge

**Date**: 2026-06-12
**Status**: Accepted
**Deciders**: Platform Architecture Team

---

## Context

The monorepo had duplicated DTOs, interfaces, validation schemas, roles/permissions, business constants, and translations split across `src/`, `apps/api/src/`, and scattered files. This caused drift, inconsistency, and manual synchronization overhead.

## Decision

Create **16 independent `@gv/*` packages** under `packages/` — each serving as the single authoritative source for a specific knowledge domain.

## Package Inventory

| Package              | Domain                     |
| -------------------- | -------------------------- |
| `@gv/domain`         | Entities + Value Objects   |
| `@gv/contracts`      | API DTOs                   |
| `@gv/schemas`        | Zod validation             |
| `@gv/auth`           | Roles + Permissions        |
| `@gv/theme`          | Design tokens              |
| `@gv/design-system`  | UI components              |
| `@gv/translations`   | i18n dictionaries          |
| `@gv/localization`   | RTL/LTR + locale           |
| `@gv/branding`       | Multi-brand config         |
| `@gv/business-rules` | Business constants         |
| `@gv/config`         | Env config loaders         |
| `@gv/features`       | Feature flags              |
| `@gv/storage`        | Storage contracts          |
| `@gv/formatting`     | Locale formatters          |
| `@gv/shared-types`   | Utility types              |
| `@gv/shared`         | Utilities + SSOT validator |

## Consequences

**Positive:**

- Zero duplication of authoritative definitions
- Type-safe contracts shared between FE and BE
- Future mobile/admin/CMS apps consume same packages
- White-label support via `@gv/branding` + `@gv/theme`

**Negative:**

- 16 packages to maintain
- Path mapping required in every `tsconfig.json`
